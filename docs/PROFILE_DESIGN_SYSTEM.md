# The Engineering Archive

Saishreek Singh / Yoriichi-GOD. An original personal identity composed for GitHub's real Markdown constraints. The person is the organizing idea; the projects keep their own identities.

## Direction

An engraved scientific instrument meets the cover of an independent engineering journal. The armillary instrument is a new vector composition: graduated limbus, meridians, inclined orbits and a small reference point. Topographic lines suggest observation without pretending to be scientific data. Corner registration marks and restrained rules establish the archive format.

REGULENS informed the warm, nocturnal atmosphere: charcoal, amber, the patience of an archive. Following the user's explicit revision request, one actual synthetic-demo dashboard screenshot now appears as an authorized product specimen. The personal identity retains editorial serif typography; the app's Pixel Noir typography remains inside its screenshot. Private documents, datasets and benchmark values are excluded.

## Typography

- **Cormorant Garamond 600:** monumental two-line name and project display titles.
- **IBM Plex Mono 400:** category, status, serial labels and instrument metadata.
- **Manrope 400:** short lines inside plates.
- **GitHub native typography:** every substantive description, capability, limitation, metric and link.

The three display fonts are SIL OFL licensed. Exported SVGs contain glyph outlines, never remote fonts, embedded font binaries or browser-dependent text. Source strings and coordinates remain editable in `tools/build_assets.py`. Credits and original notices are in `assets/identity/FONT_NOTICES.md` and `assets/identity/licenses/`.

## Composition and hierarchy

1. **Identity / orientation:** 1600 × 500 hero, a 50–80-word introduction, repository/demo/video/evidence routes. The name remains dominant.
2. **Selected work:** six alternating side-by-side desktop plates. Each gives exactly half its inner width to the title/tagline and half to the complete screenshot, starting with text left / image right and reversing on each following project. Row height follows the screenshot's own aspect ratio, eliminating the earlier added bands beside it. Approved image files, taglines, full-size links and native descriptions remain unchanged.
3. **Disciplines:** five original line icons, five concise statements and a short verified stack.
4. **Working principle:** three editorial verbs, followed by a short explanation. This is newly proposed copy, not a historical quotation.
5. **Further archive:** Peekolitix and Lighthouse receive compact text entries.
6. **Evidence:** a compact public record with denominators, dates and interpretation boundaries.
7. **Continuity / contact:** current interests, GitHub routes and one closing line.

The rhythm comes from mirrored image/text placement, with shared charcoal frames, ivory display titles, gold rules and category labels. Metadata remains inside the text half. The colored edge rule also follows the text half so it does not cover the screenshot. No layout depends on a two-column HTML table.

## Responsive behavior

`picture` switches to separate mobile compositions below 600 CSS pixels. All six mobile project plates stack the title and tagline above a complete UI viewport. SatQuery and GhostTrace now use the same complete public screenshots as their desktop cards, replacing the earlier mobile crop and schematic. Image height follows the screenshot ratio with `meet` scaling. Hero: 800 × 940. Desktop project plates are 1600 pixels wide; the inner 1568 pixels split into two equal 784-pixel halves. The image half has no added internal margin, and its height follows the screenshot ratio. The working principle also retains its stacked mobile plate.

At approximately 332 pixels of image width, the mobile name is about 43 pixels high, project titles 27–32 pixels, and plate explanatory lines about 11 pixels. Critical facts remain 16-pixel native Markdown text. Complete UI views contain naturally small app text at phone width; all six projects have an **Open full UI** link for inspection. Supplementary serial labels are never the only place a status or claim appears.

## Asset rules

- Static SVG, outlined glyphs, explicit background, internal vector geometry and embedded WebP specimens only.
- No scripts, foreignObject, remote resources, CSS dependency, external statistics service or animation.
- A single optimized PNG hero fallback is supplied for clients that cannot display SVG. To use it, replace the hero img's src; mobile SVG remains the preferred mobile plate.
- Two unchanged public specimens are pinned by revision and verified Git blob SHA. The four replacement UI inputs have original and output SHA-256 records in `tools/ui_sources.json`. Their complete viewports are preserved, and optimized standalone WebP copies provide full-size access. User PNG originals remain local and ignored.
- REGULENS uses the explicitly authorized actual dashboard on fictional records. GhostTrace uses its public synthetic-case investigation UI on both desktop and mobile. The earlier diagrams are superseded.
- No UI screens are generated, repainted or presented as new product functionality.

## Acceptance standard

The cover must identify Saishreek before the visitor scrolls; project purpose must be understandable without decoding artwork. Each graphic must be readable or deliberately supplementary at mobile size. Claims must survive source inspection. The visual-QA record, rather than this design intent, determines what was actually checked.
